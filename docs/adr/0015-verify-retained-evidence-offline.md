# Verify retained evidence offline

Analysis callers had to restate the collector's integrity rules in prose before trusting a retained bundle. Add an offline `verify` command that selects the observation behind a saved collector result, or the unique interrupted or failed PR-head observation after a caller-supplied start time, and checks it with the collector's own validators. ADR-0002 still holds: `verify` reports evidence facts and an exact-baseline state, while report decisions, signature comparison, and causal analysis stay in the analysis skills.

Warm-suite reuse during collection and `verify` share one retained-summary check: raw index, summary digest and identity, counts, failure files re-derived from the indexed JUnit, binary inventory, and symlink-free paths. Rerun lineage keeps two drivers over the same extracted checks. Collection may still refetch a missing source through acquisition, while `verify` walks the lineage offline and reports a missing source as damaged evidence. A root manifest that a later observation replaced still validates when it agrees on identity, suite states, and errors, as the analysis contract requires; a replacement with different states is reported as superseded and prevents a fully verified result. An exact-baseline state requires the caller's PR and head pins.
